# Hull Breach: фронтенд (UI, HUD, мобильное управление)

Интерфейс для общего проекта Hull Breach: Unity 2D, C#, Android, горизонтальная ориентация.
Это не отдельная игра. Интерфейс только вызывает методы игрового модуля и слушает его события.
Комнаты, ИИ врагов, бой, награды, сохранение и прокачка остаются на стороне бэкенда.

> **Статус проверки.** Код написан без доступа к Unity и компилятору C#.
> Он **не компилировался и не запускался** ни в редакторе, ни на Android.
> Выполнена только статическая проверка: баланс скобок, сверка всех имён и сигнатур с исходниками
> бэкенда (API v1.0), число аргументов в вызовах фабрики UI, подключение `using`.
> Первый шаг интеграции: открыть проект и убедиться, что он собирается (см. «Чек-лист»).
> Список рисков: `KNOWN_ISSUES.md`.

## Требования

- Unity 2022.3 LTS или новее (Unity 6 допустим). Код использует C# 9, без `record` и `init`.
- Пакеты: **TextMeshPro** (Window → TextMeshPro → Import TMP Essential Resources) и uGUI. В Unity 6 они входят в состав `com.unity.ugui`.
- Бэкенд проекта (`Assets/HullBreach`, сборка `HullBreach.Gameplay`) лежит в том же проекте.
- Android: Minimum API Level 24+. Разрешение на вибрацию Unity добавит само, если используется `Handheld.Vibrate`.

## Установка (5 шагов)

1. Скопировать папку `Assets/HullBreachUI` в `Assets/` проекта рядом с `Assets/HullBreach`.
2. Импортировать TMP Essentials (если ещё не сделано).
3. **Шрифт с кириллицей.** Стандартный `LiberationSans SDF` из TMP Essentials не обязан содержать русские буквы в статическом атласе.
   - Взять свободный шрифт с кириллицей (например, Exo 2, Russo One, Play, Jura из Google Fonts, лицензия OFL; наличие кириллицы проверьте).
   - Window → TextMeshPro → Font Asset Creator → **Atlas Population Mode: Dynamic** → Generate → Save.
   - Assets → Create → Hull Breach → UI Theme → назначить `Body Font` (и при желании `Title Font`).
   - Назначить тему в поле `Theme` у `HullBreachUIBootstrap`.
   - Без этого русский текст может отображаться квадратами.
4. Project Settings:
   - Player → Android → Resolution and Presentation → **Default Orientation: Auto Rotation**, разрешены только Landscape Left и Landscape Right.
   - Player → Other Settings → **Active Input Handling: Both** (или Input Manager (Old)). Подробности ниже в разделе про ввод.
5. Добавить интерфейс в сцену: меню **Hull Breach → UI → Add UI Bootstrap To Scene**.
   Либо вручную: пустой GameObject → компонент `HullBreachUIBootstrap`.

Canvas, CanvasScaler, SafeArea, EventSystem и все экраны создаются кодом при старте. Руками собирать иерархию не нужно.

## Быстрый старт A: песочница на заглушке (без бэкенда)

1. **Hull Breach → UI → Create UI Sandbox Scene (Mock)** → выбрать, куда сохранить сцену.
2. Нажать Play.
3. Пройти цикл: «Начать абордаж», карта сектора, точка входа, бой, награда, следующий корабль.
4. В бою справа по центру видны отладочные кнопки: урон, зачистка, +ресурсы, смерть робота.
   Удерживайте кнопку атаки: заглушка убивает врагов. Навык убивает до трёх.
5. Победа на пятом корабле (боссе «Нексус-Прайм») показывает экран победы.

Заглушка (`Mock/MockGameHost`) не является игровой логикой проекта. Числа условные, ничего не сохраняется на диск.

## Быстрый старт B: с реальным бэкендом

1. Подготовить сцену по `INTEGRATION.md` бэкенда: `GameStateManager`, `ProgressionSystem`, `ModuleSystem`, `ShipRunManager`, объект игрока с `PlayerController` и `PlayerCombat`, камера, префабы комнат и врагов (это зона бэкенда).
2. Добавить `HullBreachUIBootstrap` (режим `Auto`). Он найдёт системы сам, в том числе неактивный объект игрока.
   Либо перетащить ссылки в блок «Ссылки на бэкенд».
3. В консоли должна появиться строка `Подключён игровой модуль (бэкенд)`.
   Если вместо неё `Работает заглушка`, прочитайте причину в сообщении (какой компонент не найден).
4. Режим `Backend` в Inspector пишет ошибку в консоль, если что-то не найдено, и запускает заглушку.
5. Поле `World Camera` нужно для привязки чисел урона и маркера цели к мировым координатам. Пусто означает `Camera.main`.

## Как устроен интерфейс

```
HullBreachUI (Canvas: Screen Space Overlay, sorting 100; CanvasScaler 1920x1080, match = высота)
├── Backdrop            фон меню: космос, параллакс, «обшивка» (отключается в бою)
├── SafeArea            под вырезы и жестовую панель (Screen.safeArea + отступ 14)
│   └── Screens         8 основных экранов; виден один
├── Fx                  виньетка урона, числа урона, маркер цели (на весь экран)
├── Modals              подтверждение, настройки, пауза
└── Overlay             тосты и отладочная панель заглушки
```

- Высота холста всегда 1080 единиц, ширина подстраивается под экран (от 4:3 до 21:9). Карточки лежат в LayoutGroup и сжимаются по ширине, но не ниже минимума.
- Один основной экран за раз: `UIManager` скрывает старый, потом показывает новый. Запросы во время перехода не теряются, побеждает последний.
- UI **ничего не решает про состояние игры**. Показывает экран по `StateChanged`, а действия игрока превращает в команды сервисов.

### Состояние игры → экран

| GameState | Экран | Класс |

## Мобильное управление

- **Стик слева.** Зона касания: левые 46% безопасной области и нижние 62% высоты. Палец можно ставить в любое место зоны.
  Режимы: фиксированный (по умолчанию) и плавающий (в настройках). Вектор отправляется бэкенду **каждый кадр**, пока палец на экране.
- **Атака справа внизу.** Удержание: автоатака с автонаведением бэкенда. Кольцо краснеет, когда у робота есть цель.
- **Навык справа выше.** Радиальная перезарядка, секунды в центре, дрожание кнопки при попытке нажать на перезарядке. Над кнопкой атаки показаны активные модули с перезарядкой (они срабатывают вместе с навыком).
- **Мультитач.** Каждый палец имеет свой `pointerId`, поэтому стик, атака и навык работают одновременно.
- **Не мешают полю.** Элементы прижаты к углам, центр свободен. Занято: стик до 46% ширины и 62% высоты слева, кнопки около 450x350 единиц справа внизу, верхняя полоса около 150 единиц.
- **Настройки (PlayerPrefs, ключи `hb_ui_*`).** Громкость, вибрация, числа урона, режим стика, размер и прозрачность кнопок. Игровой прогресс UI не сохраняет.
- **Пауза.** Кнопка в правом верхнем углу, системная «Назад» и автопауза при сворачивании. Реализована через `Time.timeScale = 0`; при выходе из боя масштаб времени возвращается.

### Про ввод (важно)

- Экранные элементы работают на `EventSystem` и поддерживают оба бэкенда ввода. При включённом **только** новом Input System `EventSystemGuard` добавляет `InputSystemUIInputModule` через рефлексию.
- Если в сцене уже есть `EventSystem` со `StandaloneInputModule`, а активен только новый Input System, в консоль выводится предупреждение. Замените модуль кнопкой «Replace with InputSystemUIInputModule» или включите `Both`.
- Кнопка «Назад» (Esc) читается через старый Input Manager. При только новом Input System вызовите `UIManager.HandleBack()` из своего `InputAction`.

## Подключение финального арта

Всё работает на временных ресурсах, нарисованных кодом (`ProceduralSprites`). Заменять по частям через `UITheme` (Assets → Create → Hull Breach → UI Theme):

| Ключ | Что заменяет |
|---|---|
| `panel`, `panel_edge` | 9-slice панель и её рамка (в спрайте задайте Border) |
| `bar`, `bar_edge` | плашки полос и пипсов |
| `circle`, `ring` | круглые кнопки и кольца |
| `vignette` | красная виньетка урона |
| `grid` | «обшивка» фона меню |
| `icon.<имя>` | иконки (список ниже) |

Имена иконок: `shield`, `bubble`, `bolt`, `core`, `chevrons`, `crosshair`, `plus`, `close`, `emp`, `injector`, `hex`, `gear`, `crate`, `radar`, `pause`, `back`, `arrow_right`, `play`, `check`, `lock`, `ship_a`, `ship_b`, `ship_c`, `ship_boss`, `robot_samurai`, `robot_techno`.
Соответствие модулей и иконок: `Theme/UIIcons.cs`. Спрайты белые, красятся через `Image.color`. Если подставляете цветные, цвет карточки будет их тонировать.

Шрифты задаются в `UITheme` (`Body Font`, `Title Font`). Тексты интерфейса собраны в `Framework/UIStrings.cs` (задел под локализацию); названия модулей и описания приходят из бэкенда.

## Чек-лист первой интеграции

1. [ ] Проект собирается без ошибок. Если нет, пришлите список ошибок. Скорее всего это мелочи: опечатки и версия API TMP.
2. [ ] Песочница запускается, весь цикл проходится на заглушке.
3. [ ] Русский текст отображается нормально (шрифт с кириллицей назначен).
4. [ ] Сцена с бэкендом: в консоли `Подключён игровой модуль (бэкенд)`.
5. [ ] В бою стик двигает робота, атака бьёт, навык срабатывает, после зачистки комнаты баннер и двери.
6. [ ] На телефоне: стик и кнопки работают одновременно двумя пальцами.
7. [ ] На телефоне с вырезом: ничего не залезает под вырез и жестовую панель.
8. [ ] Пауза замораживает бой, продолжить возвращает, свернуть и развернуть игру ставит паузу.
9. [ ] Смерть: экран смерти показывает ресурсы и сохранённый прогресс; «Начать заново» создаёт новую карту.
10. [ ] Прокачка: покупка меняет уровень и ресурсы; в бою здоровье и урон растут (это проверка бэкенда).

## Как расширять

- **Новый экран.** Класс от `UIScreen` (метод `Build`, при необходимости `OnShown`/`OnHidden`), добавить `ScreenId` и строку `AddScreen<...>` в `UIManager.Initialize`.
- **Свой источник данных.** Реализуйте контракты из `Scripts/Contracts` и положите в `UIServices`. Так сделана заглушка.
- **Префабы вместо кода.** `Build()` каждого экрана можно заменить загрузкой префаба, контракты и логика навигации от этого не меняются.
