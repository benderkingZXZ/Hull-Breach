# KNOWN_ISSUES.md: риски и ограничения

## Главное

**Код не компилировался и не запускался.** Работа велась без Unity и компилятора C#.
Выполнено: статический анализ (баланс скобок во всех файлах; сверка имён и сигнатур с исходниками бэкенда API v1.0; проверка числа аргументов во всех вызовах `UIFactory`; проверка `using`). Этого недостаточно, чтобы гарантировать сборку.

Вероятные места первых ошибок компиляции (если будут):
- версия API TextMeshPro в Unity 6: свойство `enableWordWrapping` помечено устаревшим (предупреждение, не ошибка);
- мелкие опечатки и ошибки областей видимости, которые статический анализ не ловит;
- `Object.FindObjectOfType` в `Editor/HullBreachUIMenu.cs` в Unity 6 даёт предупреждение об устаревании.

Если проект не соберётся, присылайте текст ошибок: они исправляются точечно.

## Не проверено на устройстве

- Реальное мультитач-поведение (стик и кнопки двумя пальцами) на Android.
- Вырезы и скруглённые углы (`Screen.safeArea`) на конкретных телефонах.
- Производительность на слабых устройствах. Известно: иконки и панели рисуются при первом обращении (около 20 небольших текстур), фон меню держит две текстуры звёзд.
- Размеры и расположение элементов на всех соотношениях сторон (проектировалось под 4:3 … 21:9; карточки сжимаются по ширине, но не ниже 300 единиц).

## Ограничения реализации

1. **Шрифт.** Нужен TMP-шрифт с кириллицей, иначе русский текст отображается квадратами (инструкция в `README.md`).
2. **Графика временная.** Панели, иконки, силуэты кораблей и роботов нарисованы кодом. Это силуэты-заглушки, не финальный арт. Замена через `UITheme`.
3. **Кнопки круглые, зона нажатия прямоугольная.** Углы квадрата вокруг круглой кнопки тоже реагируют на касание (проверка по прозрачности требует читаемых текстур).
4. **Ввод.** Esc/«Назад» читается только через старый Input Manager (`ENABLE_LEGACY_INPUT_MANAGER`). При только новом Input System вызовите `UIManager.HandleBack()` из `InputAction`.
5. **Иконки модулей общие**: у модулей из `ModuleId` есть по одной иконке, у редкостей отличается только цвет.
6. **Вибрация.** `Handheld.Vibrate()` имеет фиксированную длительность; вызывается редко (не чаще раза в 1,5 с и только при крупном уроне). Тонкой настройки нет.
7. **Числа урона и маркер цели** требуют камеры игрового мира (`World Camera` или `Camera.main`). Без неё числа не показываются, остальное работает.
8. **Заглушка.** `MockGameHost`: числа условные, ничего не сохраняется, мир не отображается (в песочнице нет комнат). Её задача: пройти экраны и проверить HUD.
9. **Настройки звука.** Ползунок громкости меняет `AudioListener.volume`; звуков в проекте пока нет.
10. **Пауза** меняет `Time.timeScale`; если бэкенд позже начнёт сам менять `timeScale`, потребуется договорённость (предложение в `FRONTEND_API.md`, п. 9).
11. **Локализация.** Тексты собраны в `UIStrings`, но часть строк (подписи карточек, баннеры) пока написана прямо в экранах.
12. **Экран победы** показывает силуэт флагмана, перечёркнутый крестом (код-графика), анимации разрушения нет.
13. **Данные бэкенда.** Подписи вида «Итог зависит от точки входа» и список из 4 кораблей опираются на текущие правила проекта; при изменении правил обновите `UIStrings.SectorShipCount` и тексты.

## Известные особенности бэкенда, обойдённые в UI

См. `FRONTEND_API.md`, п. 5: порядок `StateChanged`/`ShipStarted`, сброс ввода при смене комнат, неактивный игрок вне боя, отсутствие событий для щита и перезарядки.
